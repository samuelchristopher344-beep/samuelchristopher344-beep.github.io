Improvement

Iterative Development

In build

Refining designs based on testing results so future versions are stronger, smarter, and more efficient.

Version numbers, even for a first build

The current drone frame is version one. Motors and electronics will make version two of the same machine, not a different project. Keeping that continuity is how a prototype becomes a series.

Each version should change one main thing, so the test result has a cause.

The loop

  • Build the smallest version that can be tested
  • Write what failed, in plain language
  • Change one primary variable
  • Test again and keep the notes with the photos

What this site records

Photos of the drone frame are the first artifact in that loop. Later pages will add electronics, then flight notes. The record is the product as much as the machine is.
